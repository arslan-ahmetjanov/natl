Instalación

Necesitas Node.js 18+ y una terminal.

npm install -g @natl/cli @natl/adapter-playwright
npx playwright install chromium
natl --version

Si natl --version imprime un número, estás dentro. Si no — Troubleshooting.

Proyecto vacío (el ejemplo apunta al sandbox en vivo):

mkdir my-tests && cd my-tests
natl init
natl run tests/

Credenciales del sandbox: demo@natl.dev / secret. Gemelo offline: examples/fixtures/sandbox.html en el repo (cambia base_url en natl.config.yaml).

Primera ejecución

Tras natl init, natl run tests/ abre el sandbox de docs, inicia sesión y hace ping a un JSON estático. Hace falta red para la URL de Pages (o apunta base_url al fixture local).

También hay un login de ejemplo con HTML local en el repo:

git clone https://github.com/arslan-ahmetjanov/natl.git
cd natl/examples
natl run login.yaml

Deberías ver ✓ PASS. Rompe a propósito el texto del assert, ejecuta de nuevo, lee la línea FAIL y arréglalo — así aprendes el runner.

Anatomía del escenario

name: Login smoke
engine: playwright
tags: [smoke]
timeout: 15000
retries: 0
vars:
  base_url: ./fixtures/shop.html
  user: demo@test.com
  pass: secret
steps:
  - goto: $base_url
  - fill: "#email"
    with: $user
  - fill: "#password"
    with: $pass
  - click: "#login-btn"
  - assert: ".welcome"
    text: "Добро пожаловать"

Campos raíz que soporto:

FieldMeaning
nameNombre para mostrar (informes, --grep)
tagsEtiquetas para --tags
engineplaywright | selenium | cypress | http
timeoutTimeout de paso por defecto (ms)
retriesIntentos extra del escenario completo tras fallo
varsVariables ($name)
secretsCómo cargar secretos
importsRutas Page / YAML compartido
elements / actionsLocalizadores POM y flujos con nombre
locator_strategyPredeterminado para selectores string (css | xpath)
casesFilas data-driven
dataArray como $data para for:
before_each / after_eachHooks alrededor de steps en cada intento
stepsLista principal de pasos

Por paso también puedes fijar timeout, save, debug. Para cambiar de engine a mitad del escenario, usa un bloque with: — eso es lo que honra el runtime.

Config del proyecto y env

natl.config.yaml (el más cercano subiendo desde el archivo de test):

engine: playwright
browser: chromium
timeout: 15000
base_url: https://staging.example.com
headless: true
viewport: { width: 1280, height: 720 }
locator_strategy: css
artifacts_dir: artifacts
retries: 0
trace: on-fail
video: off
soft_assert_screenshot: false

Funciona sin copiar URLs en cada archivo:

natl run tests/ --env staging
natl run tests/ --config config/prod.yaml

--env carga config/<name>.yaml. --env y --config son mutuamente excluyentes.

Prioridad de merge: CLI → test YAML → perfil env → config base → defaults.

Pasos UI

VerbForm
gotoURL, file:// o ruta relativa → archivo local
click / tapMismo paso; prefiere click:
filllocator + hermano with:
selectlocator + with: (valor de opción)
check / unchecklocator
waitms, o selector + visible | hidden | attached | detached
 
- goto: $base_url
- fill: "#email"
  with: $user
- select: "#country"
  with: "KZ"
- check: "#agree"
- click: "#submit"
- wait: 500
- wait: ".modal hidden"

Auto-wait: actions y asserts esperan el objetivo dentro de timeout. Normalmente no necesitas wait: ".ok visible" antes de un assert.

Assert

- assert: ".welcome"
  text: "Hello"              # or is:
- assert: ".welcome"
  contains: "Hell"
- assert: $welcome
  visible: true
- assert: ".banner"
  hidden: true
- assert: ".price"
  attr: class contains "sale"
- assert: current_url == "https://example.com/app"
- assert: current_url contains "/app"
- assert: $ping.status == 200
- assert: ".price"
  text: "$10"
  soft: true
- soft_assert: ".stock"      # alias → soft: true
  visible: true

Operadores de attr: ==, !=, contains, matches. Soft asserts acumulan fallos y fallan al final; hard assert es fail-fast.

Extract, set, log, screenshot

- get_text: ".title"
  save: title
- get_attr: "a"
  attr: href
  save: href
- set: $total = $price * $qty
- log: "total=$total"
- log: { message: "x", level: warn }   # info|debug|warn|error
- debug: true
- screenshot:
    file: artifacts/shot.png
    full_page: true

Gestos

Mismos pasos para desktop y mobile web — sin if: mobile.

- scroll: "#footer"
  into_view: true            # or delta_x / delta_y
- swipe: "#carousel"
  direction: left            # left|right|up|down
  distance: 200
- long_press: "#card"
  duration_ms: 700

Vars, secrets, expressions

SyntaxMeaning
$userVariable
$order.idCampo anidado
$env.KEYEntorno / .env (ausente → error)
$secret.KEYMismo almacén; enmascarado en logs
${ENV:KEY}Compat legacy
 
secrets:
  env:
    file: .env
    encoding: utf-8

vars:
  user: $env.TEST_USER
  pass: $secret.TEST_PASS

Operadores: == != > < >= <= contains matches and or not.

Builtins: now, today, random_int, random_string, random_uuid, random_email, len, contains, trim, upper, lower, replace, match, join, map, filter, range.

El runtime también inyecta current_url para comprobaciones de URL. Ver examples/env_login.yaml.

Page objects

# pages/login.yaml
locator_strategy: css
elements:
  email: "#email"
  title:
    strategy: xpath
    value: "//h1"
actions:
  login:
    - fill: $email
      with: $user
    - fill: "#password"
      with: $pass
    - click: "#login-btn"

# scenario
imports:
  - pages/login.yaml
steps:
  - goto: $base_url
  - do: login.login
    user: $user
    pass: $pass
  - include: login/login
    vars: { user: $user }

do: page.action es el camino feliz. include: es la forma de bajo nivel (archivo o reutilización de archivo completo). Las claves hermanas en do: se fusionan en el scope de la action.

Los archivos Page pueden omitir steps. natl run tests/ omite pages/ y config/.

Prioridad de strategy: objeto element → page locator_strategy → proyecto → css.

Cases y data

cases:
  - { name: user1, user: "a@test.com", pass: secret, expect: "Welcome, A" }
  - { label: user2, user: "b@test.com", pass: secret, expect: "Welcome, B" }
steps:
  - fill: "#email"
    with: $user
  - assert: ".welcome"
    text: $expect

data:
  - { name: one }
  - { name: two }
steps:
  - for: $item in $data
    steps:
      - log: $item.name

Prefiere cases: para tablas simples; data: + for: para bucles anidados / calculados. El sufijo del informe usa name / label de la fila, si no [case N].

HTTP

engine: http
vars:
  base_url: http://127.0.0.1:8765
steps:
  - get: $base_url/get
    save: ping
  - post: $base_url/post
    headers: { X-Test: "1" }
    body: { hello: world }
    save: echo
  - put: …
  - patch: …
  - delete: …
  - assert: $echo.status == 200
  - assert: $echo.ok == true

Forma guardada: { status, headers, body, ok }. Las URLs relativas se resuelven contra vars.base_url cuando es http(s). El legacy api: sigue funcionando — prefiere los verbos.

UI + API en un archivo:

engine: playwright
steps:
  - goto: $base_url
  - with: http
    steps:
      - get: $api_base/get
        save: ping
      - assert: $ping.status == 200
  - click: "#refresh"

Mis demos HTTP necesitan el stub primero:

node stubs/echo-server.mjs
natl run http_only.yaml
natl run ui_http_block.yaml

Flow

- if: $role == "admin"
  then:
    - click: "#admin"
  else:
    - click: "#user"

- for: $i in range(1, 5)
  steps:
    - log: $i

- repeat: 3                 # or "3 times" / times: 3
  steps:
    - click: "#next"        # sets $i

- repeat:
    until: $done == true
  steps:
    - click: "#poll"        # max 1000 iterations

- parallel:                 # wait: all (default) | any
  - get: $api/a
    save: a
  - get: $api/b
    save: b

before_each / after_each se ejecutan alrededor de steps en cada intento (incluidos retries).

Tags, retries, CLI

name: Checkout
tags: [smoke, checkout]
retries: 1
natl run tests/ --tags smoke,auth    # OR
natl run tests/ --grep "Login"       # RegExp on name or path
natl run tests/ --retries 2
natl run tests/ --env staging
natl run tests/ --headed
natl run tests/ --engine selenium
natl run tests/ --trace on-fail
natl run tests/ --video off

--tags y --grep se combinan con AND. Cero coincidencias → exit 1. Retries vuelve a ejecutar todo el escenario con un contexto de navegador nuevo; gana el último intento.

Forma compacta y sugar

Principal (commitea esto — YAML válido):

- fill: "#email"
  with: $user
- wait: ".dashboard visible"
- assert: ".welcome"
  text: "Hello"

Runtime sugar (preprocesador; los IDEs pueden marcarlo):

- fill: "#email" with: $user
- assert: ".welcome" text: "Hello"
- scroll: $footer into_view

Autocompletado IDE: conecta schemas de @natl/core vía yaml.schemas — ver el README del CLI.
