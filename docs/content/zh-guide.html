安装

你需要 Node.js 18+ 和一个终端。

npm install -g @natl/cli @natl/adapter-playwright
npx playwright install chromium
natl --version

如果 natl --version 输出版本号，说明安装成功。否则请看 Troubleshooting。

创建自己的空项目：

mkdir my-tests && cd my-tests
natl init
natl run tests/

首次运行

克隆仓库并运行我放在 examples/ 下的 login 示例（本地 HTML 夹具——不依赖不稳定的公网站点）：

git clone https://github.com/arslan-ahmetjanov/natl.git
cd natl/examples
natl run login.yaml

你应该看到 ✓ PASS。故意改错 assert 文本，再运行一次，阅读 FAIL 行，然后修复——这就是学习 runner 的方式。

场景结构

name: Login smoke
engine: playwright
tags: [smoke]
timeout: 15000
retries: 0
vars:
  base_url: ./fixtures/shop.html
  user: demo@test.com
  pass: secret
steps:
  - goto: $base_url
  - fill: "#email"
    with: $user
  - fill: "#password"
    with: $pass
  - click: "#login-btn"
  - assert: ".welcome"
    text: "Добро пожаловать"

我支持的根级字段：

FieldMeaning
name显示名称（报告、--grep）
tags用于 --tags 的标签
engineplaywright | selenium | cypress | http
timeout默认步骤超时（毫秒）
retries失败后额外完整场景重试次数
vars变量（$name）
secrets密钥加载方式
importsPage / 共享 YAML 路径
elements / actionsPOM 定位器与命名流程
locator_strategy字符串选择器默认值（css | xpath）
cases数据驱动行
data作为 $data 供 for: 使用的数组
before_each / after_each每次尝试围绕 steps 的钩子
steps主步骤列表

每个步骤还可设置 timeout、save、debug。要在场景中途切换引擎，使用 with: 块——这是 runtime 实际遵循的方式。

项目配置与环境变量

natl.config.yaml（从测试文件向上查找最近的）：

engine: playwright
browser: chromium
timeout: 15000
base_url: https://staging.example.com
headless: true
viewport: { width: 1280, height: 720 }
locator_strategy: css
artifacts_dir: artifacts
retries: 0
trace: on-fail
video: off
soft_assert_screenshot: false

无需在每个文件中复制 URL：

natl run tests/ --env staging
natl run tests/ --config config/prod.yaml

--env 加载 config/<name>.yaml。--env 与 --config 互斥。

合并优先级： CLI → 测试 YAML → env 配置 → 基础 config → 默认值。

UI 步骤

VerbForm
gotoURL、file:// 或相对路径 → 本地文件
click / tap同一步骤；优先使用 click:
filllocator + 同级 with:
selectlocator + with:（选项值）
check / unchecklocator
wait毫秒，或选择器 + visible | hidden | attached | detached
 
- goto: $base_url
- fill: "#email"
  with: $user
- select: "#country"
  with: "KZ"
- check: "#agree"
- click: "#submit"
- wait: 500
- wait: ".modal hidden"

自动等待： action 和 assert 会在 timeout 内等待目标元素。通常不需要在 assert 前加 wait: ".ok visible"。

Assert

- assert: ".welcome"
  text: "Hello"              # or is:
- assert: ".welcome"
  contains: "Hell"
- assert: $welcome
  visible: true
- assert: ".banner"
  hidden: true
- assert: ".price"
  attr: class contains "sale"
- assert: current_url == "https://example.com/app"
- assert: current_url contains "/app"
- assert: $ping.status == 200
- assert: ".price"
  text: "$10"
  soft: true
- soft_assert: ".stock"      # alias → soft: true
  visible: true

属性运算符：==、!=、contains、matches。Soft assert 收集失败并在结束时失败；hard assert 是 fail-fast。

Extract、set、log、screenshot

- get_text: ".title"
  save: title
- get_attr: "a"
  attr: href
  save: href
- set: $total = $price * $qty
- log: "total=$total"
- log: { message: "x", level: warn }   # info|debug|warn|error
- debug: true
- screenshot:
    file: artifacts/shot.png
    full_page: true

手势

桌面与移动 Web 使用相同步骤——无需 if: mobile。

- scroll: "#footer"
  into_view: true            # or delta_x / delta_y
- swipe: "#carousel"
  direction: left            # left|right|up|down
  distance: 200
- long_press: "#card"
  duration_ms: 700

Vars、secrets、expressions

SyntaxMeaning
$user变量
$order.id嵌套字段
$env.KEY环境变量 / .env（缺失 → 报错）
$secret.KEY同一存储；日志中掩码
${ENV:KEY}旧版兼容
 
secrets:
  env:
    file: .env
    encoding: utf-8

vars:
  user: $env.TEST_USER
  pass: $secret.TEST_PASS

运算符：== != > < >= <= contains matches and or not。

内置函数：now、today、random_int、random_string、random_uuid、random_email、len、contains、trim、upper、lower、replace、match、join、map、filter、range。

Runtime 还会注入 current_url 用于 URL 检查。参见 examples/env_login.yaml。

Page objects

# pages/login.yaml
locator_strategy: css
elements:
  email: "#email"
  title:
    strategy: xpath
    value: "//h1"
actions:
  login:
    - fill: $email
      with: $user
    - fill: "#password"
      with: $pass
    - click: "#login-btn"

# scenario
imports:
  - pages/login.yaml
steps:
  - goto: $base_url
  - do: login.login
    user: $user
    pass: $pass
  - include: login/login
    vars: { user: $user }

do: page.action 是推荐写法。include: 是底层形式（文件或整文件复用）。do: 上的同级键会合并到 action 作用域。

Page 文件可以省略 steps。natl run tests/ 会跳过 pages/ 和 config/。

策略优先级：element 对象 → page locator_strategy → 项目 → css。

Cases 与 data

cases:
  - { name: user1, user: "a@test.com", pass: secret, expect: "Welcome, A" }
  - { label: user2, user: "b@test.com", pass: secret, expect: "Welcome, B" }
steps:
  - fill: "#email"
    with: $user
  - assert: ".welcome"
    text: $expect

data:
  - { name: one }
  - { name: two }
steps:
  - for: $item in $data
    steps:
      - log: $item.name

简单表格优先用 cases:；嵌套/计算循环用 data: + for:。报告后缀使用行的 name / label，否则为 [case N]。

HTTP

engine: http
vars:
  base_url: http://127.0.0.1:8765
steps:
  - get: $base_url/get
    save: ping
  - post: $base_url/post
    headers: { X-Test: "1" }
    body: { hello: world }
    save: echo
  - put: …
  - patch: …
  - delete: …
  - assert: $echo.status == 200
  - assert: $echo.ok == true

保存结构：{ status, headers, body, ok }。当 vars.base_url 为 http(s) 时，相对 URL 相对它解析。旧版 api: 仍可用——优先使用动词形式。

同一文件中的 UI + API：

engine: playwright
steps:
  - goto: $base_url
  - with: http
    steps:
      - get: $api_base/get
        save: ping
      - assert: $ping.status == 200
  - click: "#refresh"

我的 HTTP 演示需要先启动 stub：

node stubs/echo-server.mjs
natl run http_only.yaml
natl run ui_http_block.yaml

Flow

- if: $role == "admin"
  then:
    - click: "#admin"
  else:
    - click: "#user"

- for: $i in range(1, 5)
  steps:
    - log: $i

- repeat: 3                 # or "3 times" / times: 3
  steps:
    - click: "#next"        # sets $i

- repeat:
    until: $done == true
  steps:
    - click: "#poll"        # max 1000 iterations

- parallel:                 # wait: all (default) | any
  - get: $api/a
    save: a
  - get: $api/b
    save: b

before_each / after_each 在每次尝试（含重试）围绕 steps 运行。

Tags、retries、CLI

name: Checkout
tags: [smoke, checkout]
retries: 1
natl run tests/ --tags smoke,auth    # OR
natl run tests/ --grep "Login"       # RegExp on name or path
natl run tests/ --retries 2
natl run tests/ --env staging
natl run tests/ --headed
natl run tests/ --engine selenium
natl run tests/ --trace on-fail
natl run tests/ --video off

--tags 与 --grep 以 AND 组合。零匹配 → 退出码 1。Retries 用全新 browser context 重跑整个场景；以最后一次尝试为准。

紧凑写法与 sugar

主要写法（提交这个——有效 YAML）：

- fill: "#email"
  with: $user
- wait: ".dashboard visible"
- assert: ".welcome"
  text: "Hello"

Runtime sugar（预处理器；IDE 可能标记）：

- fill: "#email" with: $user
- assert: ".welcome" text: "Hello"
- scroll: $footer into_view

IDE 自动补全：通过 yaml.schemas 接入 @natl/core schema——见 CLI README。
