安装

需要 Node.js 18 或更高版本。

npm install -g @natl/cli @natl/adapter-playwright
npx playwright install chromium
natl --version

若输出版本号，说明安装成功。否则请参阅 Troubleshooting。

从零开始创建项目：

mkdir my-tests && cd my-tests
natl init
natl run tests/

首次运行

仓库中有一个 login 示例。它打开本地 HTML 文件，因此不需要在线网站。

git clone https://github.com/arslan-ahmetjanov/natl.git
cd natl/examples
natl run login.yaml

应看到 PASS。将 assert 文本改成错误内容，再运行一次，阅读报错信息，然后改回。这是最快了解失败呈现方式的做法。

场景结构

name: Login smoke
engine: playwright
tags: [smoke]
timeout: 15000
retries: 0
vars:
  base_url: ./fixtures/shop.html
  user: demo@test.com
  pass: secret
steps:
  - goto: $base_url
  - fill: "#email"
    with: $user
  - fill: "#password"
    with: $pass
  - click: "#login-btn"
  - assert: ".welcome"
    text: "Добро пожаловать"

文件顶部的字段：

字段作用
name显示在报告中；供 --grep 使用
tags与 --tags 配合使用
engineplaywright、selenium、cypress 或 http
timeout默认步骤超时（毫秒）
retries失败后额外完整运行的次数
vars以 $name 形式使用的值
secretssecrets 的加载来源
imports要引入的其他 YAML 文件
elements / actionsPage object 定位器与命名流程
locator_strategy字符串选择器的默认值：css 或 xpath
cases每行数据对应一次运行
data数组，供 for: 以 $data 使用
before_each / after_each每次尝试时在 steps 前后执行
steps步骤本身

单个步骤也可设置 timeout、save 或 debug。要在运行中途切换 engine，用 with: 包裹步骤。单步上的裸 engine: 不会切换上下文。

项目配置与环境变量

默认值位于测试旁的 natl.config.yaml（NATL 从当前文件向上查找，直到找到该文件）：

engine: playwright
browser: chromium
timeout: 15000
base_url: https://staging.example.com
headless: true
viewport: { width: 1280, height: 720 }
locator_strategy: css
artifacts_dir: artifacts
retries: 0
trace: on-fail
video: off
soft_assert_screenshot: false

切换环境而无需修改每个场景：

natl run tests/ --env staging
natl run tests/ --config config/prod.yaml

--env staging 会加载 config/staging.yaml。不要同时传入 --env 和 --config。

优先级从强到弱：CLI 标志 → 测试文件中的字段 → 环境 profile → natl.config.yaml → 内置默认值。

UI 步骤

步骤说明
gotohttp(s) URL、file://，或指向本地文件的相对路径
click / tap同一操作。通常写 click:
fill定位器，值通过 with: 传入
select定位器，选项值通过 with: 传入
check / uncheck复选框 / 单选框
wait毫秒延迟，或带 visible、hidden、attached、detached 的选择器
 
- goto: $base_url
- fill: "#email"
  with: $user
- select: "#country"
  with: "KZ"
- check: "#agree"
- click: "#submit"
- wait: 500
- wait: ".modal hidden"

click、fill 和 assert 已会在 timeout 内等待目标元素。assert 前很少需要 wait: ".ok visible"。将 wait: 用于延迟或 hidden 等状态。

Assert

- assert: ".welcome"
  text: "Hello"              # is: works the same
- assert: ".welcome"
  contains: "Hell"
- assert: $welcome
  visible: true
- assert: ".banner"
  hidden: true
- assert: ".price"
  attr: class contains "sale"
- assert: current_url == "https://example.com/app"
- assert: current_url contains "/app"
- assert: $ping.status == 200
- assert: ".price"
  text: "$10"
  soft: true
- soft_assert: ".stock"      # same as soft: true
  visible: true

对于 attr:，可使用 ==、!=、contains 或 matches。硬 assert 会停止运行。软 assert 会继续执行，若有失败则在结束时标记整个运行为失败。

读取值、set、log、screenshot

- get_text: ".title"
  save: title
- get_attr: "a"
  attr: href
  save: href
- set: $total = $price * $qty
- log: "total=$total"
- log: { message: "x", level: warn }   # info, debug, warn, error
- debug: true
- screenshot:
    file: artifacts/shot.png
    full_page: true

滚动、滑动、长按

桌面端与移动 Web 用法相同。无需按设备类型分支。

- scroll: "#footer"
  into_view: true            # or delta_x / delta_y
- swipe: "#carousel"
  direction: left            # left, right, up, down
  distance: 200
- long_press: "#card"
  duration_ms: 700

变量、secrets、表达式

写法含义
$user变量
$order.id嵌套字段
$env.KEY来自环境或 .env（缺失时报错）
$secret.KEY同一来源；日志中隐藏
${ENV:KEY}旧写法；仍可用
 
secrets:
  env:
    file: .env
    encoding: utf-8

vars:
  user: $env.TEST_USER
  pass: $secret.TEST_PASS

比较：== != > < >= <= contains matches and or not。

辅助函数：now、today、random_int、random_string、random_uuid、random_email、len、contains、trim、upper、lower、replace、match、join、map、filter、range。

URL 检查期间可使用 current_url。examples/env_login.yaml 中有可用示例。

Page objects

# pages/login.yaml
locator_strategy: css
elements:
  email: "#email"
  title:
    strategy: xpath
    value: "//h1"
actions:
  login:
    - fill: $email
      with: $user
    - fill: "#password"
      with: $pass
    - click: "#login-btn"

# scenario
imports:
  - pages/login.yaml
steps:
  - goto: $base_url
  - do: login.login
    user: $user
    pass: $pass
  - include: login/login
    vars: { user: $user }

普通场景中使用 do: page.action。include: 是更低层的形式，用于指定文件路径或引入整个文件。do: 旁的额外键会成为该 action 的变量。

Page 文件可以只含 elements 和 actions，不含 steps。运行文件夹时，NATL 会跳过 pages/ 和 config/。

定位器策略的优先级：元素对象 → page 文件 → 项目配置 → css。

Cases 与 data

cases:
  - { name: user1, user: "a@test.com", pass: secret, expect: "Welcome, A" }
  - { label: user2, user: "b@test.com", pass: secret, expect: "Welcome, B" }
steps:
  - fill: "#email"
    with: $user
  - assert: ".welcome"
    text: $expect

data:
  - { name: one }
  - { name: two }
steps:
  - for: $item in $data
    steps:
      - log: $item.name

表格化输入用 cases:。对列表或 range 循环用 data: 配合 for:。报告会附加行的 name 或 label；若两者都省略，则显示 [case N]。

HTTP

engine: http
vars:
  base_url: http://127.0.0.1:8765
steps:
  - get: $base_url/get
    save: ping
  - post: $base_url/post
    headers: { X-Test: "1" }
    body: { hello: world }
    save: echo
  - put: …
  - patch: …
  - delete: …
  - assert: $echo.status == 200
  - assert: $echo.ok == true

保存的内容：{ status, headers, body, ok }。相对 URL 在 vars.base_url 为 http(s) URL 时使用该值。旧的 api: 形式仍可解析；新文件应使用上述动词。

同一场景中的 UI 与 HTTP：

engine: playwright
steps:
  - goto: $base_url
  - with: http
    steps:
      - get: $api_base/get
        save: ping
      - assert: $ping.status == 200
  - click: "#refresh"

仓库中的 HTTP 示例需要本地 stub：

node stubs/echo-server.mjs
natl run http_only.yaml
natl run ui_http_block.yaml

if / for / repeat / parallel

- if: $role == "admin"
  then:
    - click: "#admin"
  else:
    - click: "#user"

- for: $i in range(1, 5)
  steps:
    - log: $i

- repeat: 3                 # or "3 times", or times: 3
  steps:
    - click: "#next"        # $i is set each time

- repeat:
    until: $done == true
  steps:
    - click: "#poll"        # stops after 1000 iterations

- parallel:                 # wait: all by default, or any
  - get: $api/a
    save: a
  - get: $api/b
    save: b

before_each 和 after_each 在每次尝试（含重试）时在 steps 前后运行。

Tags、retries、CLI

name: Checkout
tags: [smoke, checkout]
retries: 1
natl run tests/ --tags smoke,auth    # match any listed tag
natl run tests/ --grep "Login"       # regex on name or path
natl run tests/ --retries 2
natl run tests/ --env staging
natl run tests/ --headed
natl run tests/ --engine selenium
natl run tests/ --trace on-fail
natl run tests/ --video off

若同时传入 --tags 和 --grep，文件须同时匹配两者。无匹配时退出码为 1。重试会开启新的浏览器上下文并完整重新运行场景。以最后一次尝试的结果为准。

如何编写步骤

优先使用带同级键的普通 YAML。编辑器和 schema 均按此格式设计：

- fill: "#email"
  with: $user
- wait: ".dashboard visible"
- assert: ".welcome"
  text: "Hello"

runner 也接受单行写法。许多编辑器会将其标为无效 YAML，因此不建议提交：

- fill: "#email" with: $user
- assert: ".welcome" text: "Hello"
- scroll: $footer into_view

如需自动补全，将 YAML 扩展指向 @natl/core 中的 schema。CLI README 中有 yaml.schemas 配置说明。
