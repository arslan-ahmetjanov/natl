Campos raíz (YAML de escenario)

FieldMeaning
nameNombre visible (reportes, --grep)
tagsLista de strings para --tags
engineplaywright | selenium | cypress | http
timeoutTimeout de paso por defecto (ms)
retriesIntentos extra de escenario completo tras fallo
varsVariables del escenario ($name)
secretsCómo cargar secrets (ver abajo)
importsRutas YAML de página / compartidos
elementsLocators POM
actionsListas de pasos con nombre POM
locator_strategyDefault para selectores string (css | xpath)
casesFilas data-driven
dataArray expuesto como $data para for:
before_each / after_eachHooks alrededor de steps en cada intento
stepsLista principal de pasos

Cada paso también puede llevar: timeout, save, debug. Para cambiar de engine a mitad de escenario, usa un bloque with: — eso es lo que honora el runtime.

Config del proyecto y perfiles env

natl.config.yaml (el más cercano subiendo desde el archivo de test):

engine: playwright
browser: chromium          # adapter-specific
timeout: 15000
base_url: https://staging.example.com
headless: true
viewport: { width: 1280, height: 720 }
locator_strategy: css
artifacts_dir: artifacts
retries: 0
trace: on-fail             # off | on | on-fail
video: off
soft_assert_screenshot: false

Perfiles env: config/<name>.yaml vía --env staging, o cualquier overlay vía --config path.yaml (mutuamente excluyentes).

Prioridad de merge: CLI → YAML del test → perfil env → config base → defaults.

Pasos UI

VerbForm
gotogoto: $url o goto: { url, timeout } — http(s), file:// o relativo → archivo
click / tapMismo paso; prefiere click:
fillfill: "#id" + hermano with:
selectlocator + with: (valor de opción)
check / unchecklocator
waitms, o selector + visible|hidden|attached|detached

Auto-wait: acciones y asserts esperan el objetivo dentro del timeout. Prefiere assert sobre un wait: … visible redundante.

Assert

- assert: ".welcome"
  text: "Hello"            # or is:
- assert: ".welcome"
  contains: "Hell"
- assert: $welcome
  visible: true
- assert: ".banner"
  hidden: true
- assert: ".price"
  attr: class contains "sale"
- assert: current_url == "https://example.com/app"
- assert: current_url contains "/app"
- assert: $ping.status == 200
- assert: ".price"
  text: "$10"
  soft: true
- soft_assert: ".stock"    # alias → soft: true
  visible: true

Operadores de attr inline: ==, !=, contains, matches.

Los soft asserts recopilan fallos; la ejecución falla al final. El assert duro es fail-fast.

Gestos

- scroll: "#footer"
  into_view: true          # or delta_x / delta_y
- swipe: "#carousel"
  direction: left          # left|right|up|down
  distance: 200
- long_press: "#card"
  duration_ms: 700

Mismos pasos para web de escritorio y móvil. Fidelidad táctil = capacidad del adapter.

HTTP

engine: http
steps:
  - get: $base_url/health
    save: ping
  - post: $base_url/login
    headers: { Authorization: "Bearer $token" }
    body: { user: $user }
    save: resp
  - put: …
  - patch: …
  - delete: …
  - assert: $resp.status == 200

Forma guardada: { status, headers, body, ok }. URLs relativas se resuelven contra vars.base_url cuando es http(s).

Mezcla con UI:

- with: http
  steps:
    - get: $api/orders/$id
      save: order

El legacy api: sigue parseando; trabajo nuevo debe usar los verbos de arriba.

POM

# pages/login.yaml
locator_strategy: css
elements:
  email: "#email"
  title:
    strategy: xpath
    value: "//h1"
actions:
  login:
    - fill: $email
      with: $user
    - click: "#login-btn"

# scenario
imports:
  - pages/login.yaml
steps:
  - do: login.login
    user: $user
    pass: $pass
  - include: login/login   # path-style / whole-file
    vars: { user: $user }

Los archivos de página pueden omitir steps (solo elements + actions). natl run tests/ omite directorios pages/ y config/.

Prioridad de estrategia para un element: strategy del objeto → locator_strategy de la page → proyecto → css.

Cases y data

cases:
  - { name: a, user: a@test.com, expect: "A" }
  - { label: b, user: b@test.com, expect: "B" }
steps:
  - fill: "#email"
    with: $user
  - assert: ".hi"
    text: $expect

data:
  - { name: one }
  - { name: two }
steps:
  - for: $item in $data
    steps:
      - log: $item.name

Prefiere cases: para tablas simples; data: + for: para bucles anidados / calculados.

Flujo

- if: $role == "admin"
  then:
    - click: "#admin"
  else:
    - click: "#user"

- for: $i in range(1, 5)
  steps:
    - log: $i

- repeat: 3                 # or "3 times" / times: 3
  steps:
    - click: "#next"        # sets $i

- repeat:
    until: $done == true
  steps:
    - click: "#poll"        # max 1000 iterations

- parallel:                 # wait: all (default) | any
  - get: $api/a
    save: a
  - get: $api/b
    save: b

- parallel:
    wait: any
    steps:
      - get: $api/fast
      - get: $api/slow

Vars, secrets y expresiones

SyntaxMeaning
$userVariable
$order.idCampo anidado
$env.KEYEntorno / .env (ausente → error)
$secret.KEYMismo almacén; enmascarado en logs
${ENV:KEY}Compat legacy
 
secrets:
  env:
    file: .env
    encoding: utf-8

Operadores: == != > < >= <= contains matches and or not.

Builtins: now, today, random_int, random_string, random_uuid, random_email, len, contains, trim, upper, lower, replace, match, join, map, filter, range.

El runtime inyecta current_url para asserts / expresiones de URL.

Filtros CLI

natl run tests/ --tags smoke,auth    # OR
natl run tests/ --grep "Login"       # RegExp on name or path
natl run tests/ --retries 2
natl run tests/ --env staging
natl run tests/ --headed
natl run tests/ --engine selenium
natl run tests/ --trace on-fail
natl run tests/ --video off

--tags y --grep se combinan con AND. Cero coincidencias → exit 1.

Forma compacta y sugar

Principal (lo que debes commitear — YAML válido):

- fill: "#email"
  with: $user
- wait: ".dashboard visible"
- assert: ".welcome"
  text: "Hello"

Runtime sugar (preprocesador; IDEs pueden marcar como YAML inválido):

- fill: "#email" with: $user
- assert: ".welcome" text: "Hello"
- scroll: $footer into_view

Objetos anidados (fill: { locator, with }, …) son válidos para tooling.

IDE: conecta schemas de @natl/core vía la extensión YAML yaml.schemas — ver el README del CLI.
