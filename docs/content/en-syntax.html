Syntax

Source of truth in the repo: schemas under @natl/core + the interpreter. If docs and runtime disagree, trust the runtime and open an issue.

Root fields (scenario YAML)

FieldMeaning
nameDisplay name (reports, --grep)
tagsString list for --tags
engineplaywright | selenium | cypress | http
timeoutDefault step timeout (ms)
retriesExtra full-scenario attempts after failure
varsScenario variables ($name)
secretsHow to load secrets (see below)
importsPage / shared YAML paths
elementsPOM locators
actionsPOM named step lists
locator_strategyDefault for string selectors (css | xpath)
casesData-driven rows
dataArray exposed as $data for for:
before_each / after_eachHooks around steps each attempt
stepsMain step list

Every step may also carry: timeout, save, debug. To switch engines mid-scenario, use a with: block — that is what the runtime honors.

Project config & env profiles

natl.config.yaml (nearest walking up from the test file):

engine: playwright
browser: chromium          # adapter-specific
timeout: 15000
base_url: https://staging.example.com
headless: true
viewport: { width: 1280, height: 720 }
locator_strategy: css
artifacts_dir: artifacts
retries: 0
trace: on-fail             # off | on | on-fail
video: off
soft_assert_screenshot: false

Env profiles: config/<name>.yaml via --env staging, or any overlay via --config path.yaml (mutually exclusive).

Merge priority: CLI → test YAML → env profile → base config → defaults.

UI steps

VerbForm
gotogoto: $url or goto: { url, timeout } — http(s), file://, or relative → file
click / tapSame step; prefer click:
fillfill: "#id" + sibling with:
selectlocator + with: (option value)
check / unchecklocator
waitms, or selector + visible|hidden|attached|detached

Auto-wait: actions and asserts wait for the target within timeout. Prefer assert over a redundant wait: … visible.

Assert

- assert: ".welcome"
  text: "Hello"            # or is:
- assert: ".welcome"
  contains: "Hell"
- assert: $welcome
  visible: true
- assert: ".banner"
  hidden: true
- assert: ".price"
  attr: class contains "sale"
- assert: current_url == "https://example.com/app"
- assert: current_url contains "/app"
- assert: $ping.status == 200
- assert: ".price"
  text: "$10"
  soft: true
- soft_assert: ".stock"    # alias → soft: true
  visible: true

Attr operators inline: ==, !=, contains, matches.

Soft asserts collect failures; the run fails at the end. Hard assert is fail-fast.

Extract, set, log, screenshot

- get_text: ".title"
  save: title
- get_attr: "a"
  attr: href
  save: href
- set: $total = $price * $qty
- log: "hello"
- log: { message: "x", level: warn }   # info|debug|warn|error
- debug: true
- screenshot:
    file: artifacts/shot.png
    full_page: true

Gestures

- scroll: "#footer"
  into_view: true          # or delta_x / delta_y
- swipe: "#carousel"
  direction: left          # left|right|up|down
  distance: 200
- long_press: "#card"
  duration_ms: 700

Same steps for desktop and mobile web. Touch fidelity = adapter capability.

HTTP

engine: http
steps:
  - get: $base_url/health
    save: ping
  - post: $base_url/login
    headers: { Authorization: "Bearer $token" }
    body: { user: $user }
    save: resp
  - put: …
  - patch: …
  - delete: …
  - assert: $resp.status == 200

Saved shape: { status, headers, body, ok }. Relative URLs resolve against vars.base_url when it is http(s).

Mix with UI:

- with: http
  steps:
    - get: $api/orders/$id
      save: order

Legacy api: still parses; new work should use the verbs above.

POM

# pages/login.yaml
locator_strategy: css
elements:
  email: "#email"
  title:
    strategy: xpath
    value: "//h1"
actions:
  login:
    - fill: $email
      with: $user
    - click: "#login-btn"

# scenario
imports:
  - pages/login.yaml
steps:
  - do: login.login
    user: $user
    pass: $pass
  - include: login/login   # path-style / whole-file
    vars: { user: $user }

Page files may omit steps (only elements + actions). natl run tests/ skips pages/ and config/ directories.

Strategy priority for an element: object strategy → page locator_strategy → project → css.

Cases & data

cases:
  - { name: a, user: a@test.com, expect: "A" }
  - { label: b, user: b@test.com, expect: "B" }
steps:
  - fill: "#email"
    with: $user
  - assert: ".hi"
    text: $expect

data:
  - { name: one }
  - { name: two }
steps:
  - for: $item in $data
    steps:
      - log: $item.name

Prefer cases: for simple tables; data: + for: for nested / computed loops.

Flow

- if: $role == "admin"
  then:
    - click: "#admin"
  else:
    - click: "#user"

- for: $i in range(1, 5)
  steps:
    - log: $i

- repeat: 3                 # or "3 times" / times: 3
  steps:
    - click: "#next"        # sets $i

- repeat:
    until: $done == true
  steps:
    - click: "#poll"        # max 1000 iterations

- parallel:                 # wait: all (default) | any
  - get: $api/a
    save: a
  - get: $api/b
    save: b

- parallel:
    wait: any
    steps:
      - get: $api/fast
      - get: $api/slow

Vars, secrets, expressions

SyntaxMeaning
$userVariable
$order.idNested field
$env.KEYEnvironment / .env (missing → error)
$secret.KEYSame store; masked in logs
${ENV:KEY}Legacy compat
 
secrets:
  env:
    file: .env
    encoding: utf-8

Operators: == != > < >= <= contains matches and or not.

Builtins: now, today, random_int, random_string, random_uuid, random_email, len, contains, trim, upper, lower, replace, match, join, map, filter, range.

Runtime injects current_url for URL asserts / expressions.

CLI filters

natl run tests/ --tags smoke,auth    # OR
natl run tests/ --grep "Login"       # RegExp on name or path
natl run tests/ --retries 2
natl run tests/ --env staging
natl run tests/ --headed
natl run tests/ --engine selenium
natl run tests/ --trace on-fail
natl run tests/ --video off

--tags and --grep combine with AND. Zero matches → exit 1.

Compact form & sugar

Primary (what you should commit — valid YAML):

- fill: "#email"
  with: $user
- wait: ".dashboard visible"
- assert: ".welcome"
  text: "Hello"

Runtime sugar (preprocessor; IDEs may flag as invalid YAML):

- fill: "#email" with: $user
- assert: ".welcome" text: "Hello"
- scroll: $footer into_view

Nested objects (fill: { locator, with }, …) are valid for tooling.

IDE: wire @natl/core schemas via the YAML extension yaml.schemas — see the CLI README.
