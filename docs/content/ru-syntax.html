Корневые поля (YAML сценария)

ПолеСмысл
nameИмя в отчёте и для --grep
tagsСписок строк для --tags
engineplaywright | selenium | cypress | http
timeoutТаймаут шага по умолчанию (мс)
retriesДоп. попытки всего сценария после FAIL
varsПеременные ($name)
secretsКак грузить секреты
importsПути к page / shared YAML
elementsPOM-локаторы
actionsИменованные списки шагов POM
locator_strategyДефолт для строковых селекторов (css | xpath)
casesСтроки data-driven
dataМассив как $data для for:
before_each / after_eachХуки вокруг steps на попытку
stepsОсновной список шагов

У шага также: timeout, save, debug. Смена engine внутри сценария — блок with: (это то, что runtime реально переключает).

Конфиг проекта и env-профили

engine: playwright
browser: chromium
timeout: 15000
base_url: https://staging.example.com
headless: true
viewport: { width: 1280, height: 720 }
locator_strategy: css
artifacts_dir: artifacts
retries: 0
trace: on-fail
video: off
soft_assert_screenshot: false

Профили: config/<name>.yaml через --env staging, или любой оверлей через --config (взаимоисключающе).

Приоритет: CLI → YAML теста → env-профиль → base config → defaults.

UI-шаги

ГлаголФорма
gotogoto: $url или объект — http(s), file://, относительный → file
click / tapОдин шаг; предпочитаю click:
fillлокатор + with:
selectлокатор + with: (value опции)
check / uncheckлокатор
waitмс, или селектор + visible|hidden|attached|detached

Auto-wait: действия и assert ждут цель. Лишний wait: … visible перед assert обычно не нужен.

Assert

- assert: ".welcome"
  text: "Hello"
- assert: ".welcome"
  contains: "Hell"
- assert: $welcome
  visible: true
- assert: ".banner"
  hidden: true
- assert: ".price"
  attr: class contains "sale"
- assert: current_url contains "/app"
- assert: $ping.status == 200
- assert: ".price"
  text: "$10"
  soft: true
- soft_assert: ".stock"
  visible: true

Операторы в attr:: ==, !=, contains, matches. Soft — собирает ошибки; hard — fail-fast.

HTTP

engine: http
steps:
  - get: $base_url/health
    save: ping
  - post: $base_url/login
    headers: { Authorization: "Bearer $token" }
    body: { user: $user }
    save: resp
  - assert: $resp.status == 200

Также put / patch / delete. Форма ответа: { status, headers, body, ok }.

- with: http
  steps:
    - get: $api/orders/$id
      save: order

Legacy api: ещё парсится — для нового кода берите глаголы.

POM

imports:
  - pages/login.yaml
steps:
  - do: login.login
    user: $user
    pass: $pass
  - include: login/login
    vars: { user: $user }

Page-файлы могут быть без steps. natl run tests/ пропускает каталоги pages/ и config/.

Приоритет strategy: объект элемента → page → project → css.

Cases и data

cases:
  - { name: a, user: a@test.com, expect: "A" }
steps:
  - fill: "#email"
    with: $user

data:
  - { name: one }
steps:
  - for: $item in $data
    steps:
      - log: $item.name

Поток

- if: $role == "admin"
  then:
    - click: "#admin"
  else:
    - click: "#user"
- for: $i in range(1, 5)
  steps:
    - log: $i
- repeat: 3
  steps:
    - click: "#next"
- repeat:
    until: $done == true
  steps:
    - click: "#poll"
- parallel:
    - get: $api/a
      save: a
    - get: $api/b
      save: b

Компактная форма и sugar

Primary (коммитьте это — валидный YAML):

- fill: "#email"
  with: $user
- assert: ".welcome"
  text: "Hello"

Runtime sugar (препроцессор; IDE может ругаться):

- fill: "#email" with: $user
- assert: ".welcome" text: "Hello"

Схемы IDE: @natl/core → yaml.schemas в README CLI.
