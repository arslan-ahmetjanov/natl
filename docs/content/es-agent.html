Agent

@natl/agent convierte un git diff en un borrador de NATL YAML vía un LLM compatible con OpenAI y lo valida con la misma barra que natl validate. No sustituye escribir tests a mano ni ejecutar natl run.

Qué hace

natl run responde: ¿pasa el escenario? natl-agent responde: ¿qué smoke proponer para este PR?

  1. Diff contra la base
  2. Parse semántico (Tree-sitter + heurística)
  3. Contexto few-shot desde YAML en test_roots
  4. LLM → JSON/YAML → normalize → validate
  5. Self-healing opcional
  6. Publicación: comentario PR/MR o stdout

Instalación y config

npm install -D @natl/agent @natl/cli

Crea natl-agent.yml (no commits de API keys):

llm:
  provider: openai   # openai | ollama | azure | custom
  endpoint: https://api.openai.com/v1
  api_key: ${LLM_API_KEY}
  model: gpt-4o-mini
  parameters:
    temperature: 0
  json_mode: true
mode: stdout
test_roots: [tests, examples]
self_healing:
  enabled: false
  max_retries: 2

Ollama local: provider: ollama, endpoint: http://127.0.0.1:11434/v1, json_mode: false. Plantillas: examples/natl-agent.*.yml.

Primera ejecución local

export LLM_API_KEY=sk-...   # omitir con Ollama
natl-agent --config natl-agent.yml --mode stdout --base origin/main

Copia el borrador a tests/, ajusta selectores/URLs, luego natl validate y natl run.

GitHub Actions

Plantilla: examples/.github/workflows/natl-agent.yml. Hace falta fetch-depth: 0, secreto OPENAI_API_KEY y pull-requests: write para mode: comment.

- uses: actions/checkout@v4
  with:
    fetch-depth: 0
- uses: ./agent
  with:
    openai_api_key: ${{ secrets.OPENAI_API_KEY }}
    base_ref: origin/${{ github.base_ref }}
    mode: comment
    config: natl-agent.yml

En un repo consumidor: action composite del árbol NATL, o npm install -g @natl/agent y llamar natl-agent.

GitLab CI

Plantilla: examples/ci/gitlab-ci.yml. Por defecto NATL_AGENT_MODE=stdout. Para nota en MR: NATL_AGENT_MODE=comment y variables masked LLM_API_KEY + GITLAB_TOKEN.

Jenkins

Plantilla: examples/ci/Jenkinsfile. Credencial llm-api-key; parámetros AGENT_MODE y COMMENT_PROVIDER.

Generar y luego correr en CI

  • Job A — natl-agent: sugerencia + validate; comment o stdout
  • Review — persona edita YAML en tests/
  • Job B — natl run sobre la suite aceptada

No auto-commits a main sin revisión.

Límites y revisión

  • Diff vacío o no soportado → poca o ninguna sugerencia
  • Modelos locales muy pequeños solo para humo del pipeline; en CI preferir clase gpt-4o-mini u Ollama ≥3B
  • El gate de validate no se relaja
