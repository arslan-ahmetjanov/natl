Установка

Нужен Node.js 18 или новее.

npm install -g @natl/cli @natl/adapter-playwright
npx playwright install chromium
natl --version

Если печатается версия — всё в порядке. Если нет, смотрите Сбои.

Пустой проект с нуля (пример бьёт в живую песочницу):

mkdir my-tests && cd my-tests
natl init
natl run tests/

Логин песочницы: demo@natl.dev / secret. Offline: examples/fixtures/sandbox.html в репо (пропишите base_url в natl.config.yaml).

Первый прогон

После natl init команда natl run tests/ открывает sandbox на Pages, логинится и пингует статический JSON. Нужна сеть (или локальный fixture в base_url).

В репозитории также есть пример логина на локальном HTML:

git clone https://github.com/arslan-ahmetjanov/natl.git
cd natl/examples
natl run login.yaml

Должен быть PASS. Поменяйте текст assert на неверный, запустите снова, прочитайте ошибку и верните как было. Так быстрее всего понять, как выглядят FAIL.

Форма сценария

name: Sandbox login smoke
engine: playwright
tags: [smoke]
timeout: 15000
retries: 0
vars:
  base_url: ./fixtures/sandbox.html
  user: demo@natl.dev
  pass: secret
steps:
  - goto: $base_url
  - fill: "#email"
    with: $user
  - fill: "#password"
    with: $pass
  - click: "#login-btn"
  - assert: ".welcome"
    text: "Welcome, demo"

Поля в начале файла:

ПолеЗачем
nameВ отчёте; для --grep
tagsДля --tags
engineplaywright, selenium, cypress или http
timeoutТаймаут шага по умолчанию, мс
retriesСколько ещё раз прогнать весь сценарий после FAIL
varsЗначения как $name
secretsОткуда брать секреты
importsДругие YAML-файлы
elements / actionsЛокаторы и именованные действия POM
locator_strategyДефолт для строковых селекторов: css или xpath
casesПо одному прогону на строку
dataМассив как $data для for:
before_each / after_eachВокруг steps на каждую попытку
stepsСами шаги

У шага можно задать timeout, save, debug. Сменить engine посреди сценария — через блок with:. Одиночный engine: на шаге контекст не переключает.

Конфиг проекта и env

Общие настройки — в natl.config.yaml рядом с тестами (NATL ищет файл вверх по каталогам):

engine: playwright
browser: chromium
timeout: 15000
base_url: https://staging.example.com
headless: true
viewport: { width: 1280, height: 720 }
locator_strategy: css
artifacts_dir: artifacts
retries: 0
trace: on-fail
video: off
soft_assert_screenshot: false

Разные стенды без правки каждого сценария:

natl run tests/ --env staging
natl run tests/ --config config/prod.yaml

--env staging грузит config/staging.yaml. Вместе --env и --config передавать нельзя.

Приоритет, от сильного к слабому: флаги CLI, поля в YAML теста, env-профиль, natl.config.yaml, встроенные defaults.

UI-шаги

ШагЗаметки
gotohttp(s), file:// или относительный путь к локальному файлу
click / tapОдно и то же. Обычно пишу click:
fillЛокатор, значение через with:
selectЛокатор и value опции через with:
check / uncheckЧекбокс / radio
waitЗадержка в мс или селектор с visible, hidden, attached, detached
 
- goto: $base_url
- fill: "#email"
  with: $user
- select: "#country"
  with: "KZ"
- check: "#agree"
- click: "#submit"
- wait: 500
- wait: ".modal hidden"

Клики, fill и assert уже ждут цель до timeout. Перед assert редко нужен wait: ".ok visible". wait: оставляйте для паузы или состояний вроде hidden.

Assert

- assert: ".welcome"
  text: "Hello"
- assert: ".welcome"
  contains: "Hell"
- assert: $welcome
  visible: true
- assert: ".banner"
  hidden: true
- assert: ".price"
  attr: class contains "sale"
- assert: current_url contains "/app"
- assert: $ping.status == 200
- assert: ".price"
  text: "$10"
  soft: true
- soft_assert: ".stock"
  visible: true

В attr: можно ==, !=, contains, matches. Жёсткий assert останавливает прогон. Soft продолжает и в конце падает, если хоть один soft не прошёл.

Чтение значений, set, log, screenshot

- get_text: ".title"
  save: title
- get_attr: "a"
  attr: href
  save: href
- set: $total = $price * $qty
- log: "total=$total"
- log: { message: "x", level: warn }
- debug: true
- screenshot:
    file: artifacts/shot.png
    full_page: true

Scroll, swipe, long press

Одинаково на desktop и mobile web. Отдельной ветки под устройство нет.

- scroll: "#footer"
  into_view: true
- swipe: "#carousel"
  direction: left
  distance: 200
- long_press: "#card"
  duration_ms: 700

Переменные, секреты, выражения

ЗаписьСмысл
$userПеременная
$order.idВложенное поле
$env.KEYОкружение или .env (если нет — ошибка)
$secret.KEYТо же; в логах скрыто
${ENV:KEY}Старый вид; ещё работает
 
secrets:
  env:
    file: .env
    encoding: utf-8

vars:
  user: $env.TEST_USER
  pass: $secret.TEST_PASS

Сравнения: == != > < >= <= contains matches and or not.

Функции: now, today, random_int, random_string, random_uuid, random_email, len, contains, trim, upper, lower, replace, match, join, map, filter, range.

Для проверок URL есть current_url. Пример: examples/env_login.yaml.

Page objects

# pages/login.yaml
locator_strategy: css
elements:
  email: "#email"
  title:
    strategy: xpath
    value: "//h1"
actions:
  login:
    - fill: $email
      with: $user
    - fill: "#password"
      with: $pass
    - click: "#login-btn"

# scenario
imports:
  - pages/login.yaml
steps:
  - goto: $base_url
  - do: login.login
    user: $user
    pass: $pass
  - include: login/login
    vars: { user: $user }

В обычных сценариях — do: page.action. include: — когда нужен путь к файлу или целый файл. Лишние ключи рядом с do: становятся переменными для действия.

Page-файл может содержать только elements и actions. При прогоне каталога NATL пропускает pages/ и config/.

Стратегия локатора: объект элемента, потом page-файл, потом конфиг проекта, потом css.

Cases и data

cases:
  - { name: user1, user: "a@test.com", pass: secret, expect: "Welcome, A" }
  - { label: user2, user: "b@test.com", pass: secret, expect: "Welcome, B" }
steps:
  - fill: "#email"
    with: $user
  - assert: ".welcome"
    text: $expect

data:
  - { name: one }
  - { name: two }
steps:
  - for: $item in $data
    steps:
      - log: $item.name

Таблица входов — cases:. Циклы по спискам или range — data: и for:. В отчёт попадает name или label строки, иначе [case N].

HTTP

engine: http
vars:
  base_url: http://127.0.0.1:8765
steps:
  - get: $base_url/get
    save: ping
  - post: $base_url/post
    headers: { X-Test: "1" }
    body: { hello: world }
    save: echo
  - put: …
  - patch: …
  - delete: …
  - assert: $echo.status == 200
  - assert: $echo.ok == true

В переменную кладётся { status, headers, body, ok }. Относительные URL берутся от vars.base_url, если это http(s). Старый api: ещё разбирается; в новых файлах лучше глаголы выше.

engine: playwright
steps:
  - goto: $base_url
  - with: http
    steps:
      - get: $api_base/get
        save: ping
      - assert: $ping.status == 200
  - click: "#refresh"

HTTP-примеры в репо ждут локальный stub:

node stubs/echo-server.mjs
natl run http_only.yaml
natl run ui_http_block.yaml

if / for / repeat / parallel

- if: $role == "admin"
  then:
    - click: "#admin"
  else:
    - click: "#user"

- for: $i in range(1, 5)
  steps:
    - log: $i

- repeat: 3
  steps:
    - click: "#next"

- repeat:
    until: $done == true
  steps:
    - click: "#poll"

- parallel:
  - get: $api/a
    save: a
  - get: $api/b
    save: b

before_each и after_each — вокруг steps на каждую попытку, включая retries.

Tags, retries, CLI

name: Checkout
tags: [smoke, checkout]
retries: 1
natl run tests/ --tags smoke,auth
natl run tests/ --grep "Login"
natl run tests/ --retries 2
natl run tests/ --env staging
natl run tests/ --headed
natl run tests/ --engine selenium

Если переданы и --tags, и --grep, файл должен совпасть с обоими. Ноль совпадений — exit code 1. Retry запускает весь сценарий заново в новом контексте браузера. Считается последняя попытка.

Как писать шаги

Обычный YAML с соседними ключами — то, что ждут редакторы и схема:

- fill: "#email"
  with: $user
- wait: ".dashboard visible"
- assert: ".welcome"
  text: "Hello"

Однострочный вид раннер тоже съест, но многие редакторы пометят его как невалидный YAML. В репозиторий я бы так не коммитил:

- fill: "#email" with: $user
- assert: ".welcome" text: "Hello"
- scroll: $footer into_view

Автодополнение: схемы из @natl/core, настройка yaml.schemas — в README CLI.
