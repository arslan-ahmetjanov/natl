Установка

Нужны Node.js 18+ и терминал.

npm install -g @natl/cli @natl/adapter-playwright
npx playwright install chromium
natl --version

Если natl --version печатает число — вы внутри. Если нет — Сбои.

Свой пустой проект:

mkdir my-tests && cd my-tests
natl init
natl run tests/

Первый прогон

Клонируйте репозиторий и прогоните login из examples/ (локальный HTML — без чужого сайта):

git clone https://github.com/arslan-ahmetjanov/natl.git
cd natl/examples
natl run login.yaml

Должен быть ✓ PASS. Сломайте текст assert нарочно, запустите снова, прочитайте FAIL, почините — так учится раннер.

Анатомия сценария

name: Login smoke
engine: playwright
tags: [smoke]
timeout: 15000
retries: 0
vars:
  base_url: ./fixtures/shop.html
  user: demo@test.com
  pass: secret
steps:
  - goto: $base_url
  - fill: "#email"
    with: $user
  - fill: "#password"
    with: $pass
  - click: "#login-btn"
  - assert: ".welcome"
    text: "Добро пожаловать"

Корневые поля:

ПолеСмысл
nameИмя в отчёте и для --grep
tagsМетки для --tags
engineplaywright | selenium | cypress | http
timeoutТаймаут шага по умолчанию (мс)
retriesДоп. попытки всего сценария после FAIL
varsПеременные ($name)
secretsКак грузить секреты
importsПути к page / shared YAML
elements / actionsPOM-локаторы и именованные потоки
locator_strategyДефолт для строковых селекторов (css | xpath)
casesСтроки data-driven
dataМассив как $data для for:
before_each / after_eachХуки вокруг steps на попытку
stepsОсновной список шагов

У шага также: timeout, save, debug. Смена engine внутри сценария — блок with:.

Конфиг проекта и env

engine: playwright
browser: chromium
timeout: 15000
base_url: https://staging.example.com
headless: true
viewport: { width: 1280, height: 720 }
locator_strategy: css
artifacts_dir: artifacts
retries: 0
trace: on-fail
video: off
soft_assert_screenshot: false
natl run tests/ --env staging
natl run tests/ --config config/prod.yaml

--env грузит config/<name>.yaml. --env и --config взаимоисключающие.

Приоритет: CLI → YAML теста → env-профиль → base config → defaults.

UI-шаги

ГлаголФорма
gotoURL, file:// или относительный путь → локальный файл
click / tapОдин шаг; предпочитаю click:
fillлокатор + with:
selectлокатор + with: (value опции)
check / uncheckлокатор
waitмс, или селектор + visible | hidden | attached | detached
 
- goto: $base_url
- fill: "#email"
  with: $user
- select: "#country"
  with: "KZ"
- check: "#agree"
- click: "#submit"
- wait: 500
- wait: ".modal hidden"

Auto-wait: действия и assert ждут цель в пределах timeout. Обычно не нужен wait: ".ok visible" перед assert.

Assert

- assert: ".welcome"
  text: "Hello"
- assert: ".welcome"
  contains: "Hell"
- assert: $welcome
  visible: true
- assert: ".banner"
  hidden: true
- assert: ".price"
  attr: class contains "sale"
- assert: current_url contains "/app"
- assert: $ping.status == 200
- assert: ".price"
  text: "$10"
  soft: true
- soft_assert: ".stock"
  visible: true

Операторы в attr:: ==, !=, contains, matches. Soft собирает ошибки; hard — fail-fast.

Vars, secrets, expressions

СинтаксисСмысл
$userПеременная
$order.idВложенное поле
$env.KEYОкружение / .env
$secret.KEYТо же; маскируется в логах
${ENV:KEY}Совместимость
 
secrets:
  env:
    file: .env
    encoding: utf-8

vars:
  user: $env.TEST_USER
  pass: $secret.TEST_PASS

Операторы: == != > < >= <= contains matches and or not.

Builtins: now, today, random_int, random_string, random_uuid, random_email, len, contains, trim, upper, lower, replace, match, join, map, filter, range.

Runtime также подставляет current_url. Пример: examples/env_login.yaml.

Page objects

# pages/login.yaml
locator_strategy: css
elements:
  email: "#email"
  title:
    strategy: xpath
    value: "//h1"
actions:
  login:
    - fill: $email
      with: $user
    - fill: "#password"
      with: $pass
    - click: "#login-btn"

# scenario
imports:
  - pages/login.yaml
steps:
  - goto: $base_url
  - do: login.login
    user: $user
    pass: $pass
  - include: login/login
    vars: { user: $user }

do: page.action — основной путь. include: — ниже уровнем. Соседние ключи у do: попадают в scope экшена.

Page-файлы могут быть без steps. natl run tests/ пропускает pages/ и config/.

Приоритет strategy: объект элемента → page → project → css.

Cases и data

cases:
  - { name: user1, user: "a@test.com", pass: secret, expect: "Welcome, A" }
  - { label: user2, user: "b@test.com", pass: secret, expect: "Welcome, B" }
steps:
  - fill: "#email"
    with: $user
  - assert: ".welcome"
    text: $expect

data:
  - { name: one }
  - { name: two }
steps:
  - for: $item in $data
    steps:
      - log: $item.name

Для простых таблиц — cases:; для вложенных циклов — data: + for:.

HTTP

engine: http
vars:
  base_url: http://127.0.0.1:8765
steps:
  - get: $base_url/get
    save: ping
  - post: $base_url/post
    headers: { X-Test: "1" }
    body: { hello: world }
    save: echo
  - assert: $echo.status == 200

Также put / patch / delete. Форма ответа: { status, headers, body, ok }. Legacy api: ещё работает.

engine: playwright
steps:
  - goto: $base_url

    steps:
      - get: $api_base/get

Поток

- if: $role == "admin"
  then:
    - click: "#admin"
  else:
    - click: "#user"

- for: $i in range(1, 5)
  steps:
    - log: $i

- repeat: 3
  steps:
    - click: "#next"

- repeat:
    until: $done == true
  steps:
    - click: "#poll"

- parallel:
  - get: $api/a
    save: a
  - get: $api/b
    save: b

before_each / after_each — вокруг steps на каждую попытку.

Tags, retries, CLI

name: Checkout
tags: [smoke, checkout]
retries: 1
natl run tests/ --tags smoke,auth
natl run tests/ --grep "Login"
natl run tests/ --retries 2
natl run tests/ --env staging
natl run tests/ --headed
natl run tests/ --engine selenium

--tags — OR; с --grep — AND. Ноль совпадений → exit 1. Retries — весь сценарий заново, свежий контекст.

Компактная форма и sugar

Primary (коммитьте это — валидный YAML):

- fill: "#email"
  with: $user
- assert: ".welcome"
  text: "Hello"

Runtime sugar (препроцессор; IDE может ругаться):

- fill: "#email" with: $user
- assert: ".welcome" text: "Hello"

Схемы IDE: @natl/core → yaml.schemas в README CLI.
