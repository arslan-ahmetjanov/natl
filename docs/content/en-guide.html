Install

You need Node.js 18+ and a terminal.

npm install -g @natl/cli @natl/adapter-playwright
npx playwright install chromium
natl --version

If natl --version prints a number, you're in. If not — Troubleshooting.

Own empty project:

mkdir my-tests && cd my-tests
natl init
natl run tests/

First run

Clone the repo and run the login I keep under examples/ (local HTML fixture — no flaky public site):

git clone https://github.com/arslan-ahmetjanov/natl.git
cd natl/examples
natl run login.yaml

You should see ✓ PASS. Break the assert text on purpose, run again, read the FAIL line, then fix it — that's how you learn the runner.

Scenario anatomy

name: Login smoke
engine: playwright
tags: [smoke]
timeout: 15000
retries: 0
vars:
  base_url: ./fixtures/shop.html
  user: demo@test.com
  pass: secret
steps:
  - goto: $base_url
  - fill: "#email"
    with: $user
  - fill: "#password"
    with: $pass
  - click: "#login-btn"
  - assert: ".welcome"
    text: "Добро пожаловать"

Root fields I support:

FieldMeaning
nameDisplay name (reports, --grep)
tagsLabels for --tags
engineplaywright | selenium | cypress | http
timeoutDefault step timeout (ms)
retriesExtra full-scenario attempts after failure
varsVariables ($name)
secretsHow to load secrets
importsPage / shared YAML paths
elements / actionsPOM locators and named flows
locator_strategyDefault for string selectors (css | xpath)
casesData-driven rows
dataArray as $data for for:
before_each / after_eachHooks around steps each attempt
stepsMain step list

Per step you may also set timeout, save, debug. To switch engines mid-scenario, use a with: block — that is what the runtime honors.

Project config & env

natl.config.yaml (nearest walking up from the test file):

engine: playwright
browser: chromium
timeout: 15000
base_url: https://staging.example.com
headless: true
viewport: { width: 1280, height: 720 }
locator_strategy: css
artifacts_dir: artifacts
retries: 0
trace: on-fail
video: off
soft_assert_screenshot: false

Stands without copying URLs into every file:

natl run tests/ --env staging
natl run tests/ --config config/prod.yaml

--env loads config/<name>.yaml. --env and --config are mutually exclusive.

Merge priority: CLI → test YAML → env profile → base config → defaults.

UI steps

VerbForm
gotoURL, file://, or relative path → local file
click / tapSame step; prefer click:
filllocator + sibling with:
selectlocator + with: (option value)
check / unchecklocator
waitms, or selector + visible | hidden | attached | detached
 
- goto: $base_url
- fill: "#email"
  with: $user
- select: "#country"
  with: "KZ"
- check: "#agree"
- click: "#submit"
- wait: 500
- wait: ".modal hidden"

Auto-wait: actions and asserts wait for the target within timeout. You usually do not need wait: ".ok visible" before an assert.

Assert

- assert: ".welcome"
  text: "Hello"              # or is:
- assert: ".welcome"
  contains: "Hell"
- assert: $welcome
  visible: true
- assert: ".banner"
  hidden: true
- assert: ".price"
  attr: class contains "sale"
- assert: current_url == "https://example.com/app"
- assert: current_url contains "/app"
- assert: $ping.status == 200
- assert: ".price"
  text: "$10"
  soft: true
- soft_assert: ".stock"      # alias → soft: true
  visible: true

Attr operators: ==, !=, contains, matches. Soft asserts collect failures and fail at the end; hard assert is fail-fast.

Extract, set, log, screenshot

- get_text: ".title"
  save: title
- get_attr: "a"
  attr: href
  save: href
- set: $total = $price * $qty
- log: "total=$total"
- log: { message: "x", level: warn }   # info|debug|warn|error
- debug: true
- screenshot:
    file: artifacts/shot.png
    full_page: true

Vars, secrets, expressions

SyntaxMeaning
$userVariable
$order.idNested field
$env.KEYEnvironment / .env (missing → error)
$secret.KEYSame store; masked in logs
${ENV:KEY}Legacy compat
 
secrets:
  env:
    file: .env
    encoding: utf-8

vars:
  user: $env.TEST_USER
  pass: $secret.TEST_PASS

Operators: == != > < >= <= contains matches and or not.

Builtins: now, today, random_int, random_string, random_uuid, random_email, len, contains, trim, upper, lower, replace, match, join, map, filter, range.

Runtime also injects current_url for URL checks. See examples/env_login.yaml.

Page objects

# pages/login.yaml
locator_strategy: css
elements:
  email: "#email"
  title:
    strategy: xpath
    value: "//h1"
actions:
  login:
    - fill: $email
      with: $user
    - fill: "#password"
      with: $pass
    - click: "#login-btn"

# scenario
imports:
  - pages/login.yaml
steps:
  - goto: $base_url
  - do: login.login
    user: $user
    pass: $pass
  - include: login/login
    vars: { user: $user }

do: page.action is the happy path. include: is the lower-level form (file or whole-file reuse). Sibling keys on do: merge into the action scope.

Page files may omit steps. natl run tests/ skips pages/ and config/.

Strategy priority: element object → page locator_strategy → project → css.

Cases & data

cases:
  - { name: user1, user: "a@test.com", pass: secret, expect: "Welcome, A" }
  - { label: user2, user: "b@test.com", pass: secret, expect: "Welcome, B" }
steps:
  - fill: "#email"
    with: $user
  - assert: ".welcome"
    text: $expect

data:
  - { name: one }
  - { name: two }
steps:
  - for: $item in $data
    steps:
      - log: $item.name

Prefer cases: for simple tables; data: + for: for nested / computed loops. Report suffix uses row name / label, else [case N].

HTTP

engine: http
vars:
  base_url: http://127.0.0.1:8765
steps:
  - get: $base_url/get
    save: ping
  - post: $base_url/post
    headers: { X-Test: "1" }
    body: { hello: world }
    save: echo
  - put: …
  - patch: …
  - delete: …
  - assert: $echo.status == 200
  - assert: $echo.ok == true

Saved shape: { status, headers, body, ok }. Relative URLs resolve against vars.base_url when it is http(s). Legacy api: still works — prefer the verbs.

UI + API in one file:

engine: playwright
steps:
  - goto: $base_url
  - with: http
    steps:
      - get: $api_base/get
        save: ping
      - assert: $ping.status == 200
  - click: "#refresh"

My HTTP demos need the stub first:

node stubs/echo-server.mjs
natl run http_only.yaml
natl run ui_http_block.yaml

Flow

- if: $role == "admin"
  then:
    - click: "#admin"
  else:
    - click: "#user"

- for: $i in range(1, 5)
  steps:
    - log: $i

- repeat: 3                 # or "3 times" / times: 3
  steps:
    - click: "#next"        # sets $i

- repeat:
    until: $done == true
  steps:
    - click: "#poll"        # max 1000 iterations

- parallel:                 # wait: all (default) | any
  - get: $api/a
    save: a
  - get: $api/b
    save: b

before_each / after_each run around steps on every attempt (including retries).

Tags, retries, CLI

name: Checkout
tags: [smoke, checkout]
retries: 1
natl run tests/ --tags smoke,auth    # OR
natl run tests/ --grep "Login"       # RegExp on name or path
natl run tests/ --retries 2
natl run tests/ --env staging
natl run tests/ --headed
natl run tests/ --engine selenium
natl run tests/ --trace on-fail
natl run tests/ --video off

--tags and --grep combine with AND. Zero matches → exit 1. Retries re-run the whole scenario with a fresh browser context; last attempt wins.

Compact form & sugar

Primary (commit this — valid YAML):

- fill: "#email"
  with: $user
- wait: ".dashboard visible"
- assert: ".welcome"
  text: "Hello"

Runtime sugar (preprocessor; IDEs may flag it):

- fill: "#email" with: $user
- assert: ".welcome" text: "Hello"
- scroll: $footer into_view

IDE autocomplete: wire @natl/core schemas via yaml.schemas — see the CLI README.
