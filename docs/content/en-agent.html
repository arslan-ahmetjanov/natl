Agent

@natl/agent turns a git diff into a suggested NATL YAML draft via an OpenAI-compatible LLM, then gates it with the same validate bar as natl validate. It does not replace writing tests by hand or running natl run.

What it does

natl run answers: does this scenario pass? natl-agent answers: what smoke could we suggest for this PR?

  1. Diff against a base ref
  2. Semantic parse (Tree-sitter + heuristic fallback)
  3. Few-shot context from existing YAML in test_roots
  4. LLM в†’ JSON/YAML в†’ normalize в†’ validate
  5. Optional self-healing retries
  6. Publish: PR/MR comment or stdout

Install and config

npm install -D @natl/agent @natl/cli

Create natl-agent.yml (do not commit API keys):

llm:
  provider: openai   # openai | ollama | azure | custom
  endpoint: https://api.openai.com/v1
  api_key: ${LLM_API_KEY}
  model: gpt-4o-mini
  parameters:
    temperature: 0
  json_mode: true
mode: stdout
test_roots: [tests, examples]
self_healing:
  enabled: false
  max_retries: 2

Local Ollama: provider: ollama, endpoint: http://127.0.0.1:11434/v1, json_mode: false. Examples: examples/natl-agent.*.yml.

First local run

export LLM_API_KEY=sk-...   # skip for Ollama
natl-agent --config natl-agent.yml --mode stdout --base origin/main

Copy the draft into tests/, edit selectors/URLs, then natl validate and natl run.

GitHub Actions

Template: examples/.github/workflows/natl-agent.yml. Needs fetch-depth: 0, secret OPENAI_API_KEY, and pull-requests: write for mode: comment.

- uses: actions/checkout@v4
  with:
    fetch-depth: 0
- uses: ./agent
  with:
    openai_api_key: ${{ secrets.OPENAI_API_KEY }}
    base_ref: origin/${{ github.base_ref }}
    mode: comment
    config: natl-agent.yml

In a consumer repo either vendor the composite action from the NATL tree or install CLI: npm install -g @natl/agent and call natl-agent in a step. See examples/.github/workflows/natl-agent.yml.

GitLab CI

Template: examples/ci/gitlab-ci.yml. Default NATL_AGENT_MODE=stdout (dry-run in the job log). For an MR note set NATL_AGENT_MODE=comment and masked LLM_API_KEY + GITLAB_TOKEN.

Jenkins

Template: examples/ci/Jenkinsfile. Credential llm-api-key; parameters AGENT_MODE and COMMENT_PROVIDER (auto / github / gitlab / stdout).

Generate then run in CI

  • Job A вЂ” natl-agent: suggest + validate gate; publish comment or stdout
  • Review вЂ” human edits YAML into tests/
  • Job B вЂ” natl run on the accepted suite (same pattern as the guide / examples CI)

Avoid auto-committing drafts into main without review. If you need an immediate dry run of the draft, keep it as a workflow artifact and run validate there вЂ” do not treat it as the suite source of truth.

Limits and review

  • Empty or unsupported diffs в†’ little or no suggestion
  • Small local models are for pipeline smoke only; prefer gpt-4o-mini-class or Ollama в‰Ґ3B in CI
  • Agent never weakens the validate gate; self-healing retries, then still fails if invalid

More detail: package README @natl/agent and examples/ci/.
