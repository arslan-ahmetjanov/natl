Agent

@natl/agent превращает git diff в черновик NATL YAML через OpenAI-совместимую LLM и прогоняет его через ту же планку validate, что и natl validate. Это не замена ручным тестам и не замена natl run.

Что делает

natl run отвечает: пройдёт ли сценарий? natl-agent отвечает: какой smoke предложить по этому PR?

  1. Diff относительно базы
  2. Семантический разбор (Tree-sitter + запасной эвристический путь)
  3. Few-shot контекст из существующих YAML в test_roots
  4. LLM → JSON/YAML → normalize → validate
  5. Опциональный self-healing
  6. Публикация: комментарий в PR/MR или stdout

Установка и конфиг

npm install -D @natl/agent @natl/cli

Создайте natl-agent.yml (ключи в git не кладите):

llm:
  provider: openai   # openai | ollama | azure | custom
  endpoint: https://api.openai.com/v1
  api_key: ${LLM_API_KEY}
  model: gpt-4o-mini
  parameters:
    temperature: 0
  json_mode: true
mode: stdout
test_roots: [tests, examples]
self_healing:
  enabled: false
  max_retries: 2

Локально через Ollama: provider: ollama, endpoint: http://127.0.0.1:11434/v1, json_mode: false. Шаблоны: examples/natl-agent.*.yml.

Первый локальный прогон

export LLM_API_KEY=sk-...   # для Ollama не нужен
natl-agent --config natl-agent.yml --mode stdout --base origin/main

Скопируйте черновик в tests/, поправьте селекторы и URL, затем natl validate и natl run.

GitHub Actions

Шаблон: examples/.github/workflows/natl-agent.yml. Нужны fetch-depth: 0, секрет OPENAI_API_KEY и pull-requests: write для mode: comment.

- uses: actions/checkout@v4
  with:
    fetch-depth: 0
- uses: ./agent
  with:
    openai_api_key: ${{ secrets.OPENAI_API_KEY }}
    base_ref: origin/${{ github.base_ref }}
    mode: comment
    config: natl-agent.yml

В чужом репозитории: либо подключите composite action из дерева NATL, либо npm install -g @natl/agent и вызов natl-agent в шаге.

GitLab CI

Шаблон: examples/ci/gitlab-ci.yml. По умолчанию NATL_AGENT_MODE=stdout (dry-run в логе). Для note в MR: NATL_AGENT_MODE=comment и masked LLM_API_KEY + GITLAB_TOKEN.

Jenkins

Шаблон: examples/ci/Jenkinsfile. Credential llm-api-key; параметры AGENT_MODE и COMMENT_PROVIDER (auto / github / gitlab / stdout).

Сгенерировали — прогнали в CI

  • Job A — natl-agent: предложение + validate gate; comment или stdout
  • Review — человек правит YAML и кладёт в tests/
  • Job B — natl run по принятому suite (как в гайде / examples CI)

Не коммитьте черновики в main без глаз. Если нужен мгновенный dry-run черновика — артефакт workflow + validate, но не источник истины suite.

Ограничения и review

  • Пустой или неподдерживаемый diff → мало или нет предложений
  • Крошечные локальные модели — только smoke pipeline; в CI лучше класс gpt-4o-mini или Ollama ≥3B
  • Validate gate не ослабляется; self-healing делает retry, затем всё равно fail при невалидном YAML
