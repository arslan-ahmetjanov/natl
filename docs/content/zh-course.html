第 0 讲 — 安装与第一个 PASS

目标：在我已经写好的真实场景上看到 ✓ PASS。

你需要：Node.js 18+、终端、大约十五分钟。

npm install -g @natl/cli @natl/adapter-playwright
npx playwright install chromium
natl --version

克隆仓库并运行登录 fixture（本地 HTML——不依赖不稳定的公网站点）：

git clone https://github.com/arslan-ahmetjanov/natl.git
cd natl/examples
natl run login.yaml

通过时的那种感觉？记住它。本课程其余内容都是更多这样的体验。

试试看：故意改错断言文本，再运行一次，读 FAIL 行（文件 + 步骤）。修好它。安全地「弄坏」东西，学习就开始了。

第 1 讲 — 场景结构

和我一起打开 examples/login.yaml：

name: Login smoke
engine: playwright
tags: [smoke]
vars:
  base_url: ./fixtures/shop.html
  user: demo@test.com
  pass: secret
steps:
  - goto: $base_url
  - fill: "#email"
    with: $user
  - fill: "#password"
    with: $pass
  - click: "#login-btn"
  - assert: ".welcome"
    text: "Добро пожаловать"

从上到下：

  • name — 报告中显示的名称
  • engine — 如何驱动浏览器（默认 playwright；还有 selenium、cypress 或 http）
  • tags — 供 --tags 使用的可选标签
  • vars — 用 $user 等形式引用的值
  • steps — 脚本本身

你很快会遇到的其它根字段：timeout、retries、secrets、imports、cases、before_each / after_each、elements、actions、locator_strategy、data。完整列表 → 语法。

准备离开我的 fixture 时，搭建你自己的项目：

mkdir my-tests && cd my-tests
natl init
natl run tests/

第 2 讲 — UI 步骤与断言

我设计这些动词，是为了让冒烟测试能写在一屏里。主要节奏：目标 + 检查。

- goto: $base_url
- fill: "#email"
  with: $user
- select: "#country"
  with: "KZ"
- check: "#agree"
- click: "#submit"          # tap: is the same step
- assert: ".ok"
  text: "Done"
- assert: ".ok"
  contains: "Do"
- assert: ".banner"
  visible: true
- assert: ".banner"
  attr: class contains "active"
- assert: current_url contains "/dashboard"

自动等待：操作和断言会在 timeout 内等待目标出现。通常不需要在断言前写 wait: ".ok visible"。

显式 wait: 用于延迟（wait: 500）、hidden / attached / detached，或特殊时序。

软失败（收集错误，不立即停止）：

- assert: ".price"
  text: "$10"
  soft: true
# alias:
- soft_assert: ".stock"
  visible: true

需要后续使用某个值时，捕获并提取：

- get_text: ".title"
  save: page_title
- get_attr: "#link"
  attr: href
  save: href
- screenshot:
    file: artifacts/after-login.png
    full_page: true
- set: $total = $price * $qty
- log: "total=$total"

手势（同一套场景适用于桌面和移动 Web——无需 if: mobile）：

- scroll: "#footer"
  into_view: true
- swipe: "#carousel"
  direction: left
- long_press: "#card"
  duration_ms: 700

试试看：运行 examples/soft_assert_demo.yaml 和 examples/gestures_demo.yaml。

第 3 讲 — 变量、密钥与项目配置

$name 来自 vars（以及 case 行、include、POM 调用）。嵌套：$order.id。

密钥来自环境——切勿提交真实密码：

secrets:
  env:
    file: .env

vars:
  user: $env.TEST_USER
  pass: $secret.TEST_PASS

$env.KEY 和 $secret.KEY 读取同一存储；密钥在日志中会被掩码。见 examples/env_login.yaml。

项目默认值在 natl.config.yaml 中：

engine: playwright
browser: chromium
timeout: 15000
base_url: https://staging.example.com
headless: true
artifacts_dir: artifacts
retries: 0
trace: on-fail
video: off

多环境而不用在每个文件里复制 URL：

config/staging.yaml
config/prod.yaml

natl run tests/ --env staging
natl run tests/ --config config/prod.yaml

合并顺序（后者优先）：CLI 标志 → 测试 YAML → 环境 profile → natl.config → 默认值。

第 4 讲 — 页面对象（do:）

把选择器和命名流程放在页面文件中，从场景里调用。

# pages/login.yaml
elements:
  email: "#email"
  password: "#password"
  submit: "#login-btn"
actions:
  login:
    - fill: $email
      with: $user
    - fill: $password
      with: $pass
    - click: $submit

# pom_login.yaml
imports:
  - pages/login.yaml
steps:
  - goto: $base_url
  - do: login.login
    user: $user
    pass: $pass

do: page.action 是推荐路径。include: login/login 是更低层的形式（文件或整文件复用）。do: 上的同级键会合并进 action 作用域。

定位策略在 config / page / element 上——不是每个步骤都写。Web 目前：css、xpath。

elements:
  title:
    strategy: xpath
    value: "//h1"

试试看：在 examples/ 里运行 natl run pom_login.yaml。

第 5 讲 — 数据驱动 cases:

一个场景，多行数据。每行合并进 vars，steps 执行一次。

name: Data-driven login
cases:
  - { name: user1, user: "a@test.com", pass: secret, expect: "Welcome, A" }
  - { name: user2, user: "b@test.com", pass: secret, expect: "Welcome, B" }
steps:
  - goto: $base_url
  - fill: "#email"
    with: $user
  - fill: "#password"
    with: $pass
  - click: "#login-btn"
  - assert: ".welcome"
    text: $expect

报告名称形如 Data-driven login [user1]。在行上用 name 或 label；否则为 [case N]。

嵌套或计算型循环用 data: + for:（下一讲）。简单表格优先用 cases:。

试试看：natl run data_driven.yaml。

第 6 讲 — HTTP 与 with: http

纯 API 场景：

engine: http
vars:
  base_url: http://127.0.0.1:8765
steps:
  - get: $base_url/get
    save: ping
  - post: $base_url/post
    body: { hello: world }
    headers: { X-Test: "1" }
    save: echo
  - assert: $echo.status == 200
  - assert: $echo.ok == true

动词：get / post / put / patch / delete。保存的值：{ status, headers, body, ok }。旧版 api: 仍可用——优先用这些动词。

UI + API 在同一文件——用块切换上下文（不是每步 engine:）：

engine: playwright
steps:
  - goto: $base_url
  - with: http
    steps:
      - get: $api_base/get
        save: ping
      - assert: $ping.status == 200
  - click: "#refresh"

我的 HTTP 示例需要先启动本地 stub：

node stubs/echo-server.mjs
# other terminal:
natl run http_only.yaml
natl run ui_http_block.yaml

第 7 讲 — 流程：if / for / repeat / parallel

- if: $role == "admin"
  then:
    - click: "#admin"
  else:
    - click: "#user"

- for: $item in $data
  steps:
    - log: $item.name

- for: $i in range(1, 3)
  steps:
    - log: "i=$i"

- repeat: 3
  steps:
    - click: "#next"   # sets $i each time

- repeat:
    until: $done == true
  steps:
    - click: "#poll"

- parallel:
    - get: $api/a
      save: a
    - get: $api/b
      save: b

before_each / after_each 在每次尝试（含重试）时围绕 steps 运行。

表达式：== != > < >= <= contains matches and or not。内置函数包括 now、today、random_*、len、trim、upper、lower、range 等——见 语法 → 表达式。

第 8 讲 — 标签、重试与 CLI 过滤

name: Checkout
tags: [smoke, checkout]
retries: 1
natl run tests/ --tags smoke
natl run tests/ --tags smoke,auth
natl run tests/ --grep "Login"
natl run tests/ --retries 2
natl run suite.yaml --engine selenium
natl run suite.yaml --headed

--tags 是 OR。与 --grep 组合 → AND。零匹配 → 退出码 1。

重试会用全新的浏览器上下文重新运行整个场景。以最后一次为准；JSON 可能标记 flaky: true。

习题集

  1. 在 examples/ 里，让 login.yaml、pom_login.yaml 和 data_driven.yaml 全部通过。
  2. 用 natl init 新建文件夹。把 base_url 指向你关心的页面。写三步冒烟测试。
  3. 把选择器提取到 pages/，用 do: 调用。
  4. 添加 with: http 块检查健康端点（需要的话用 echo stub）。
  5. 打上 smoke 标签，用 --tags smoke 运行。
