Agent

@natl/agent 通过兼容 OpenAI 的 LLM，把 git diff 变成建议的 NATL YAML 草稿，并用与 natl validate 相同的门槛校验。它不能替代手写测试，也不能替代 natl run。

做什么

natl run 回答：场景能否通过？natl-agent 回答：这个 PR 可以建议怎样的 smoke？

  1. 相对基线的 diff
  2. 语义解析（Tree-sitter + 启发式回退）
  3. 从 test_roots 已有 YAML 取 few-shot 上下文
  4. LLM → JSON/YAML → normalize → validate
  5. 可选 self-healing
  6. 发布：PR/MR 评论或 stdout

安装与配置

npm install -D @natl/agent @natl/cli

创建 natl-agent.yml（不要把密钥提交进 git）：

llm:
  provider: openai   # openai | ollama | azure | custom
  endpoint: https://api.openai.com/v1
  api_key: ${LLM_API_KEY}
  model: gpt-4o-mini
  parameters:
    temperature: 0
  json_mode: true
mode: stdout
test_roots: [tests, examples]
self_healing:
  enabled: false
  max_retries: 2

本地 Ollama：provider: ollama，endpoint: http://127.0.0.1:11434/v1，json_mode: false。示例：examples/natl-agent.*.yml。

首次本地运行

export LLM_API_KEY=sk-...   # Ollama 可省略
natl-agent --config natl-agent.yml --mode stdout --base origin/main

把草稿拷到 tests/，改选择器与 URL，再 natl validate 与 natl run。

GitHub Actions

模板：examples/.github/workflows/natl-agent.yml。需要 fetch-depth: 0、密钥 OPENAI_API_KEY，以及 mode: comment 时的 pull-requests: write。

- uses: actions/checkout@v4
  with:
    fetch-depth: 0
- uses: ./agent
  with:
    openai_api_key: ${{ secrets.OPENAI_API_KEY }}
    base_ref: origin/${{ github.base_ref }}
    mode: comment
    config: natl-agent.yml

在业务仓库里可引入 NATL 的 composite action，或 npm install -g @natl/agent 后在步骤中调用 natl-agent。

GitLab CI

模板：examples/ci/gitlab-ci.yml。默认 NATL_AGENT_MODE=stdout。要写 MR note：设 NATL_AGENT_MODE=comment，并配置 masked LLM_API_KEY 与 GITLAB_TOKEN。

Jenkins

模板：examples/ci/Jenkinsfile。凭证 llm-api-key；参数 AGENT_MODE 与 COMMENT_PROVIDER。

生成后再在 CI 运行

  • Job A — natl-agent：建议 + validate；comment 或 stdout
  • Review — 人工改 YAML 并放入 tests/
  • Job B — 对已接受 suite 跑 natl run

不要在无人审阅时自动把草稿合入 main。

边界与人工审阅

  • 空的或不支持的 diff → 很少或没有建议
  • 极小本地模型仅用于打通管道；CI 建议 gpt-4o-mini 级或 Ollama ≥3B
  • validate 门槛不会放宽
